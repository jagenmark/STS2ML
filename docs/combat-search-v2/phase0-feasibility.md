# Silent A10 combat search v2 — Phase 0 feasibility

## Decision

Build **a bounded Python whole-turn planner with the pinned C# host as an offline fidelity oracle**. Start with a small, explicitly supported set of transitions, use the planner wherever the public state and reachable effects are covered, and retain the champion’s decision elsewhere. Add a learned value at the next-turn boundary, then test an explicit second player turn under public draw uncertainty. The online planner should take a public observation and return one legal action. Native execution reveals the next observation.

Python gives control over legality, stopping points, uncertainty and a deterministic work budget. The host already executes the native card, power, relic and enemy hooks, but its current restore operation restarts and replays the run. Putting the same operation behind a new RPC would remove some IPC without removing restoration or isolating the live engine. Reconsider a **native single-turn worker** if a prototype can reconstruct its state from a public schema, prove process/RNG isolation, agree with the oracle on the regression panel, and meet the same decision budget (p95 ≤12 ms at 256 child attempts). Promote full native lookahead only if it also qualifies draws, prompts and encounter RNG across all three acts. Revisit the architecture if Python still falls back on more than 20% of non-forced decisions in the prespecified priority formations after two coverage passes, or if native differential tests expose recurring mismatches on lethal ordering. Publish those rates by formation and act.

It installs that run in `RunManager.Instance`, subscribes to `CombatManager.Instance` events, and installs a scoped selector. ### Public information and deterministic work

- **Python.** Feed an allowlisted, immutable projection to both search and feature encoding, with no session, replay prefix, lobby seed/index, telemetry, action digest, raw serialization, or private RNG handle. Sorted multisets encode unordered zones. Only an observed, legally remembered top card can become a known prefix. Freeze public samples and tie order using a versioned hash of canonical public fields plus purpose and sample index. Use fixed work counts and stable accumulation/tie order. Send one physical root action already stamped by `legal_actions`. The live host alone advances the actual world. [Pile multisets](../../scripts/headless/ObservationExport.cs#L103) · [Native action validation](../../src/sts2rl/native.py#L264)
- **Native candidate.** Use an isolated process (separate manager state and data directories) with a public-only construction request. Under exact no-draw mode, stop *before* any hidden-dependent effect including random targeting, shuffle, creation or move selection. Under sampling, build a canonical multiset of publicly distinguishable card variants, canonicalize *before* permuting, deal without replacement, and initialize every RNG reachable during the horizon from a separate versioned sample key. Use the same worlds across competing actions and compare expectations. Hidden persistent state must be reconstructed from public evidence, marginalized under a documented distribution, or excluded. Stable ties among serialized-identical objects are safe only after proving that the objects are interchangeable for the horizon. Swap tests should include equal-looking duplicates with divergent internal fields.
- **Existing sampler.** `training_sample` shuffles the actual backing list in the worker and resets Run and Player RNGs in place. Broad sampling also resets monster-local, encounter and global Chaotic RNGs, preserves the current telegraph and cached move history, and only admits Act 1 profiles without known draw-order effects. Existing `CombatSearch` uses a second process, restores the live prefix and samples each branch. This is useful offline scaffolding. The unmodified sampler provides no proof that cached history, equal-looking cards, future spawns or other reachable RNG owners are independent of the real world. Treat actual replay follow-ups as offline observations or deterministic transition witnesses. Never give their hidden branch information to the deployed search. - **Verify both isolation and information flow.** Run off and shadow on under the same locked command stream. Compare every chosen/physical action, public response digest, prompt, reward, route, RNG-canary suffix and terminal result, with timing held in separate logs. Exercise repeated and reordered queries, different hash seeds and worker counts, and a stalled or failing worker. Separately vary hidden draw permutations, private RNG, equivalent hidden identifiers or lobby seed while holding the planner projection fixed. ### Planning horizon and budgets

Phase 1 searches every admitted root through End Turn or the next unresolved reveal. Use width **8**, depth **10** player decisions (including potion and prompt choices, with an independent cap on triggered events), and **256 attempted child transitions** per decision. Keep End Turn available at each stable play state. If a root is broad, check each legal supported first action and allocate a fixed minimum continuation quota to the champion first action and the no-potion stratum. Split retained slots between low HP loss and future progress, preserving setup prefixes such as zero-energy gain and pending discard. Deduplicate only on all future-relevant state including timing, zones, latent queues, counters, target bindings and spent potions. Retain one canonical representative per equivalence class and track its root. Reuse within a single query only until public successor matching has been proven. Tie-break toward the champion when comparably ranked, then the canonical external action order. Publish cap hits, fallback reasons and coverage.

Use the work cap to derive a **12 ms p95** target in Phase 1. There is no wall-clock-dependent cutoff that chooses a different move under load. An external watchdog can stop or mark an unhealthy episode; tune fixed caps on development fixtures before a freeze. At a cap, compare completed safe continuations. If the champion’s continuation or another legal alternative cannot be compared reliably, keep the champion. For A/B coverage checks, report both the heuristic improvement and the rate of state/legality mismatches. Test representative orderings by replaying each action and comparing the next public observation and root legal set with the projected one.

**Draws and horizon 2.** A Phase 1 unknown draw is a boundary with a known prefix of effects only. Record draw count, available hand space, shuffle requirement, changed zones, pending effects and any earlier energy gain. A subsequent native prompt or play view becomes the next root. With an exhaustive small set in Phase 2, branch by public multiplicities without replacement and aggregate all outcomes before comparing actions. For larger sets, start with four fixed public sample worlds for each of the top two qualified current-turn continuations, evaluated with common sample keys and separate next-turn plans conditioned only on observed simulated draws/intents. Consume deck/discard multisets correctly across reshuffles and handle known retained cards and a public top prefix. Unknown intent/generation gets the same treatment only when its distribution is qualified. Apply fixed total budgets including the chance descendants (initially ≤384 attempted children, ≤64 full feature/value calls, p95 ≤20 ms on four workers). Aggregate by expectation with a separate certified immediate death bound where possible. Never maximize over favorable samples or let a downstream policy see unobserved cards in a sampled world. If an outcome set or trigger cannot be represented, end at the corresponding supported leaf or fall back. This provides two-turn pressure for Sandpit, Reattach, Knowledge Demon curses and Waterfall where the needed timers and next phases are public; it does not commit to speculative actions on a future hand.

**Leaf contract.** Evaluate the End Turn successor immediately before the next unknown reveal, after resolving all known effects. Keep distinct leaf types for resolved terminal outcomes, completed turn, and unresolved mid-turn boundaries. Prefer certified survival over a deterministic immediate death. Compare complete candidates using a frozen phase-aware heuristic initially: HP, marginal enemy progress versus End Turn including already lethal Poison, pressure from upcoming telegraphs, carry-over Block/hand/powers, and explicit deadlines. ## Ranked risks and open questions

1. **Lethal model error or false clear.** Establish native action-level agreement on ordered hooks and boss phase tests before using those paths. Determine which of enemy attack order, Reattach slots/timers, intent state, Sloth counters and prompt operations are inferable from current public views. Request a versioned public field only when it has an observable equivalent.
2. **Information leakage and mutation.** Audit all data paths, including duplicate card state, prompt source, debug counters and offline replay. Can a native worker rebuild a useful root without touching the real object graph, run seed, or persistent hidden move state? A small isolated no-draw experiment can test that construction if Python coverage or fidelity misses the gate.
3. **Coverage bottleneck.** Prioritize routine hand effects, major damage hooks and the audited Act 1/2 deaths. Quantify coverage by visited state, supported root and chosen branch. Keep rare effects at clear boundaries. Determine which apparent uncovered states block high-impact saves, and which can share one proven hook implementation.
4. **Value extrapolation.** The champion rarely reaches Act 3, and player turns within a fight are correlated. How much natural held data supports late-game calibration? Use separately frozen late opening strata, compare to native continuations, and require improvement on held natural lobbies before promotion.
5. **Throughput and merge pressure.** Ownership should concentrate in the new package and tests. Keep hooks off `native.py`, legacy beam internals and frozen manifests where possible. Confirm p95 inference plus packing, support-boundary budget, and 4-worker pooled throughput before scheduling the long runs. Budget roughly 1–2 engineer-weeks for Phase 1 search and priority oracle tests, a further 1–2 for initial data/feature alignment, fit and development ablations, and 2–4 working days for the exact paired runner, adjudication and review. Coverage of the long tail can exceed those estimates. A general native clone has no reliable estimate before an isolated public-state restoration prototype succeeds.

Phase 0 has no implementation blocker. Future exact cohort runs need a registry-aware adapter and runtime links. First prove a stable public projection, then dynamic legality and trigger sequencing, then ordered end-turn fidelity, then budgeted search and potion comparison, and finally the flag-off/shadow and native differential gates.
